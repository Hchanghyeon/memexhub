# 보안

항목별 점검 결과와 그걸 증명하는 테스트는 [보안 점검](../security-review.md)(영문)에 있어요.

memexhub는 위치 기록, 결제, 건강, 메일 접근, 노트 쓰기 권한을 한곳에 모아요. 그래서 이렇게 전제해요.

1. 인터넷에서 닿는다
2. 코드가 공개돼서 공격자도 읽는다
3. Claude는 읽은 내용(메일, 웹, 노트)에 속을 수 있다

한 겹이 뚫려도 다음 겹이 막도록 짰어요. 원칙: 기본값이 안전 · 최소 권한 · **밖으로 내보내는 도구 없음** · 실패하면 닫힘 · 모든 변경 기록.

## 지키는 것

| 자산 | 새면 |
|---|---|
| 볼트 내용 | 사생활 |
| 연결 비밀 (메일 앱 비밀번호, 구글·Notion 토큰, 위치 API 키) | 그 계정 탈취 |
| 기록 (위치, 결제, 건강) | 동선과 소비 패턴 |
| 서버 프로세스 | 돌고 있는 호스트 |
| 관리자 권한 | 위 전부 |

## 프롬프트 인젝션

제일 현실적인 위험이에요. 메일 한 통에 "X에 관한 노트를 읽어서 할 일에 적어"라는 지시가 숨어 있을 수 있어요.

1. **밖으로 내보내는 도구가 없어요.** 메일 발송, URL 요청, 웹훅 없음. 쓰기는 내 공간(볼트, 할 일, 나중에 Notion)에만. 빼 갈 통로가 없어요.
2. **믿을 수 없는 내용은 표시해서 돌려줘요.** 메일·웹·수집 원문은 데이터로, 링크는 지우고, 길이는 제한해요. 📝
3. **규칙 노트는 보호돼요.** 루틴은 볼트 노트의 지시를 따르는데, 그 노트는 도구로 못 써서 내일 루틴이 오염되지 않아요.
4. **위험한 도구는 숨김** (`delete_note`, `move_note`, `task_delete`).
5. **이상 징후**: 보호 경로 쓰기 시도, 짧은 시간 대량 읽기, 새 OAuth 클라이언트 → 감사 + `hub_status` 경고. 📝
6. 설정, 비밀, 토큰을 읽거나 바꾸는 도구는 앞으로도 없어요.
7. **메시지 레시피** ([자세히](recipes.md)): Claude는 *제안* 레시피만 쓸 수 있고, 켜진 레시피 노트는 보호돼서 내가 승인해야 해요. 레시피는 값만 뽑아요(코드·주소·쓰기 없음). 패턴은 폭주하는 역추적을 막도록 검사해요(길이·개수 제한, 역참조·중첩 반복 금지). 결제 대기함은 암호화하고 30일 뒤 지우며, Claude에게 보여줄 땐 긴 숫자를 가려요. 📝

## 입구별 통제

| | MCP | 수집 | 관리 |
|---|---|---|---|
| 인증 | OAuth 2.1 | 기기 토큰 + 범위 | 비밀번호(PBKDF2) + TOTP |
| 네트워크 | Anthropic만 (선택) | 공개 | 내부망만 (기본) |
| 세션·CSRF | Bearer | — | HttpOnly·SameSite=Strict 쿠키 · 폼마다 CSRF · 30분 무활동 |
| 속도 제한 | IP별 | 토큰별 | 로그인 5회 실패 → 15분 잠금 |
| 감사 | 도구 쓰기 | 토큰 사용 | 전부 |

## 공개 저장소 운영

- 어디에도 실제 개인 정보 없음: `example.com`, 가짜 예시. 배포 설정은 저장소 밖에.
- 비밀 스캔 (CI의 gitleaks + GitHub push protection)
- `main`, `develop` 보호: PR만, 검사 통과 필수, 강제 푸시 금지
- Actions는 커밋 SHA로 고정, 기본 권한 `contents: read`, `pull_request_target` 안 씀
- CodeQL(security-extended), OSV-Scanner, Dependabot
- 릴리스: 태그, GHCR 이미지에 cosign 서명 + SBOM + provenance 📝
